Дисциплина: «Мобильные приложения». Проект: `MyFirstApp` (Expo SDK 58, React Native 0.88, TypeScript).

## 1. Лабораторная работа №1
**Тема:** настройка VS Code, Node.js, Expo и Android Studio. Создание и запуск первого приложения React Native.

### Цель
Подготовить среду разработки, создать Expo-проект на шаблоне TypeScript, запустить его на телефоне через Expo Go или в эмуляторе Android и изменить экран.

### Выполненные шаги
1. Установлены VS Code, Node.js LTS и npm. Проверка версий:
   ```bash
   node --version   # v24.21.0
   npm --version    # 11.19.0
   ```
2. Проект создан командой `npx create-expo-app@latest MyFirstApp --template blank-typescript`.
3. Проект открыт в VS Code (`cd MyFirstApp`, затем `code .`). Изучены файлы `App.tsx`, `app.json`, `package.json`, папки `assets` и `node_modules`.
4. Изменены текст и цвет фона экрана (сейчас это экран входа и главный экран Campus Hub; цвета заданы в `src/theme/colors.ts`).
5. Приложение запускается командой `npx expo start`.

### Теория для ответов
| Вопрос | Ответ |
|---|---|
| **Что такое Expo?** | Платформа и набор инструментов поверх React Native. Позволяет создать проект одной командой, запустить его на телефоне без сборки нативного кода и пользоваться готовыми модулями (иконки, хранилище, статус-бар и т. д.). |
| **Зачем нужен Node.js?** | Это среда выполнения JavaScript вне браузера. На ней работают Expo CLI, сборщик Metro и TypeScript. |
| **Зачем нужен npm?** | Менеджер пакетов: устанавливает библиотеки в `node_modules` и записывает их в `package.json`. Команда `npx` запускает инструменты пакетов, например `npx expo start`. |
| **Как устроен Expo-проект?** | `App.tsx` — корневой компонент; `app.json` — настройки приложения (название, иконка, ориентация); `package.json` — зависимости и скрипты; `assets/` — изображения; `node_modules/` — установленные пакеты; `tsconfig.json` — настройки TypeScript. |
| **Для чего `App.tsx`?** | Это точка входа: Expo отображает компонент, экспортированный из `App.tsx` по умолчанию. В Campus Hub он подключает тему, данные и навигацию. |
| **Как запустить?** | `npx expo start`, затем отсканировать QR-код в Expo Go или нажать `a`, чтобы открыть Android-эмулятор. |
| **Expo Go или Android Emulator?** | Expo Go — приложение на реальном телефоне: быстро, видна реальная производительность, компьютер и телефон должны быть в одной Wi-Fi-сети. Эмулятор — виртуальный телефон из Android Studio на компьютере: телефон не нужен, легко менять модель и размер экрана, но он требует много ресурсов ПК. |

## 2. Лабораторная работа №2
**Тема:** создание экрана React Native с использованием JavaScript и TypeScript.

### Цель
Создать экран «Профиль студента» на функциональных компонентах TypeScript с использованием `View`, `Text`, `Pressable` и `StyleSheet.create()`.

### Где это реализовано в проекте
| Требование | Файл |
|---|---|
| Тип данных студента | `src/types/Student.ts`: `firstName`, `lastName`, `group`, `program` (специальность, как в методичке) |
| Карточка: ФИО, группа, специальность, кнопка «Открыть профиль» | `src/components/StudentCard.tsx` |
| Экран «Профиль студента» | `src/screens/StudentProfileScreen.tsx` и `src/components/ProfileCard.tsx` |
| Профиль текущего пользователя | `src/screens/ProfileScreen.tsx` |
| `Pressable` | все кнопки: `PrimaryButton.tsx`, `IconButton.tsx`, `ServiceCard.tsx` |
| `StyleSheet.create()` | в каждом компоненте и экране |

Кнопка «Открыть профиль» в карточке студента переходит на экран профиля и передаёт `studentId` выбранного студента. Профиль показывает данные именно этой записи, а не фиксированные демонстрационные данные.

### Теория для ответов
| Вопрос | Ответ |
|---|---|
| **Функциональный компонент** | Обычная функция, которая получает Props и возвращает JSX. Пример: `export default function StudentCard({ student }: Props) { return <View>…</View>; }` |
| **`View` и `Text`** | `View` — контейнер для разметки, работает как блок с Flexbox. `Text` — единственный компонент для вывода текста; текст вне `Text` вызывает ошибку. |
| **`Pressable`** | Обёртка, которая реагирует на нажатие (`onPress`). Через `style={({ pressed }) => …}` меняет вид в момент нажатия. |
| **Props** | Входные данные компонента, которые передаёт родитель. Только для чтения. Пример: `<StudentCard student={item} onDelete={handleDelete} />`. |
| **State** | Внутренние данные компонента, которые меняются со временем. При их изменении React перерисовывает экран. |
| **`useState`** | Хук для состояния: `const [query, setQuery] = useState('')`. `setQuery` обновляет значение и запускает перерисовку. |
| **Зачем TypeScript** | Проверяет типы до запуска. Например, нельзя открыть профиль без `studentId` или передать в карточку объект без поля `group`: ошибку покажет `npx tsc`. |
| **`StyleSheet`** | `StyleSheet.create({...})` описывает стили в стиле CSS, но в camelCase (`backgroundColor`, `fontSize`). Стили создаются один раз и проверяются типами. |
| **Как устроен профиль** | Тип `Student` → данные хранятся в `AppDataContext` и AsyncStorage → `StudentCard` показывает краткую версию → «Открыть профиль» вызывает `navigation.navigate('StudentProfile', { studentId })` → экран находит студента по id и показывает `ProfileCard`. |

### Индивидуальное задание из методички
- Аты-жөні мен тобы: добавьте себя через вкладку «Студенты» или заполните свой «Профиль».

- Вторая информационная строка: в профиле есть строки «Добавлен в список» и «Источник данных».
- Текст кнопки: «Открыть профиль» в `StudentCard.tsx`.

## 3. Структура проекта

```text
MyFirstApp/

│   │   ├── ServiceCard      # фото-карточка сервиса + избранное

│   ├── context/             # AppDataContext (сессия, студенты, избранное), CampusContext (данные сервисов)
│   ├── i18n/                # переводы RU / KZ / EN и LanguageContext
│   ├── storage/storage.ts   # единая работа с AsyncStorage
│   ├── theme/               # палитры, шрифты, отступы, ThemeContext
│   ├── data/                # данные сервисов: расписание, автобусы, меню, книги…
│   ├── hooks/               # useNow (живое время), useSignOut

│   └── utils/               # валидация, форматирование, ссылки
```

## 4. Реализованные функции
- **Дизайн** в стиле «глубокий синий космос»: тёмно-синий фон со свечением, фото-карточки, белые кнопки-«пилюли» со стрелкой ↗, круглая кнопка меню «≡», шрифт Inter.
- **Экран загрузки** при запуске приложения и после нажатия «Войти» (анимированная полоса).
- **Три языка** — русский, казахский, английский. Переключаются в меню «≡» и в настройках, выбор сохраняется.
- **Вход**: логин не менее 4 символов, пароль **не менее 8**, кнопка «показать/скрыть пароль», понятные ошибки на выбранном языке. Пароль не сохраняется.
- Сессия хранится в AsyncStorage и восстанавливается после перезапуска. Выход с подтверждением.
- **Главная**: приветствие и дата, быстрые иконки сервисов, виджеты «Следующая пара» и «Ближайший автобус» (по реальному времени), 8 фото-карточек, фильтр «Избранное».
- **Адаптивная сетка**: 2 колонки на телефоне, 3 на планшете (от 600 px). Колонки считаются через `useWindowDimensions`, ширина карточки — от фактической ширины сетки. При повороте экрана всё пересчитывается.
- **8 рабочих сервисов** на примерных данных (на каждом экране пометка «Пример — важно заполнить»):
  - **CAL Расписание** — неделя Пн–Сб, пары с аудиторией и преподавателем, подсветка «Сейчас / Далее».
  - **BUS Автобусы** — 4 маршрута (№12, 37, 63, 92). Выбор маршрута, ближайшие отправления от текущего времени, остановки, интервал, цена проезда. «Мой маршрут» показывается на главной.
  - **LIB Библиотека** — схема читального зала (30 мест: свободные и занятые), бронь места на сегодня, 6 онлайн-книг (Project Gutenberg).
  - **LMS Moodle** — курсы с прогрессом, задания с отметкой выполнения и сроками, оценки с расчётом GPA.
  - **FOOD Столовая** — 12 блюд с фото и ценами в тенге, категории, корзина, доставка (+300 ₸) или самовывоз, статус заказа. Это демо: оплата не проводится.
  - **SPORT Спорт** — абонементы (разовый, месяц, семестр) со сроком действия, режим работы, недельный план тренировок, запись в секции.
  - **DORM Общежитие** — моя комната, запись в прачечную, заявки на ремонт со статусом, гостевой пропуск с кодом, правила.
  - **INFO Информация** — новости, контакты служб со звонком в одно касание, частые вопросы.
- **Профиль**: заполнять не нужно. Показаны примерные данные с пометкой «важно заполнить», данные аккаунта и активность (заказы, избранное, абонемент).
- **Студенты** (ЛР2): добавление с проверкой, поиск, удаление с подтверждением, профиль выбранного студента, `FlatList`.
- Светлая и тёмная тема на всех экранах; выбор сохраняется.

## 5. Речь для защиты (2–3 минуты)

> Здравствуйте! Я представляю мобильное приложение **Campus Hub**. Оно объединяет университетские сервисы в одном месте.
>
> В **первой лабораторной работе** я настроил среду: установил VS Code, Node.js и npm и проверил версии командами `node --version` и `npm --version`. Затем создал Expo-проект на шаблоне TypeScript и запустил его командой `npx expo start`: на телефоне через Expo Go по QR-коду или в эмуляторе Android клавишей `a`. Expo Go работает на реальном телефоне, а эмулятор — это виртуальное устройство на компьютере.
>
> Во **второй лабораторной работе** я сделал экран «Профиль студента». Я описал тип `Student` на TypeScript: имя, фамилия, группа и специальность. Карточка студента собрана из `View` и `Text`, а кнопка «Открыть профиль» — из `Pressable`. Стили заданы через `StyleSheet.create`. Данные передаются через Props, а состояние — например, текст поиска — хранится в `useState`.
>
> Сейчас покажу приложение. *(Демонстрация.)* При запуске появляется экран загрузки. Это экран входа: пароль должен быть не короче восьми символов. Через меню можно сменить язык на казахский или английский. После входа снова показывается загрузка, затем главный экран с восемью сервисами: на телефоне две колонки, на планшете три. Каждый сервис работает: в столовой можно собрать корзину и заказать доставку, в библиотеке — забронировать свободное место, в автобусах — выбрать маршрут, и он появится на главной. На вкладке «Студенты» я добавляю студента и открываю его профиль. В настройках переключаются тема и язык.
>
> Все данные сохраняются в AsyncStorage, поэтому после перезапуска сессия, студенты, избранное и тема восстанавливаются. Код разделён на компоненты, экраны, навигацию, хранилище и тему, а TypeScript проверяет его без ошибок. Спасибо за внимание!

## 6. Ограничения (честно для защиты)
- Авторизация учебная и локальная. Это не проверка личности на сервере.
- Расписание, маршруты, меню, цены, контакты и профиль — примерные данные. Их важно заменить реальными в файлах папки `src/data/`.
- Заказы еды и абонементы — демо: оплата не проводится, всё хранится только на устройстве.
- AsyncStorage не является защищённым хранилищем, поэтому пароли в нём не хранятся.
